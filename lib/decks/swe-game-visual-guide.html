02 · FAILURE为什么画面与胜利界面都不够

画面有电池和信标，不代表拾取与存入真的发生

只看画面

cell是可拾取的电池，beacon是要存入电池的信标；把它们画出来，不保证碰撞改变状态。

只看结局

候选可能按时间自动进入胜利。没有不操作的对照，就不知胜利是否由玩家造成。

运行证据

输入控制器（driver）把定时动作送入引擎；状态探针（probe）读取对象。评测器再检查拾取、存入和进度改变。

同长度完全无输入也成功，已认证路线（certified route）的贡献记0。

04 · VISIBILITY谁看得到什么

公开接口允许替代实现，隐藏评测规则保留判分权

Agent 可见

  • 按模式给短目标、GDD、项目起点、故障项目或 Godot 源码
  • 素材与对应任务模式的参考视频
  • contract.json / Unity interface
  • 语义对象分组、输入动作与数值状态项
  • 必须交付的项目、GDD、demo 或 build 说明

只有评测器可见

  • 逐题检查条件与预期结果
  • 在参考游戏验证过的输入路线（certified routes）
  • 场景起点参数与状态探针检查要求
  • 参考、故障、修复三版本的场景判分
  • 评测器端视觉评分曲线与缺陷分数上限

公开材料说明“能观察哪些角色和状态”，不会把参考实现或隐藏判分条件交给 Agent。

07 · INTERFACE不同代码结构怎样接受同一测试

gb_levels.json 是候选填写的场景绑定，不是隐藏判分文件

01公开接口

作者规定关卡、结束场景、玩家和动作应怎样暴露。

02候选填写

gb_levels.json给出自己项目里关卡与结束场景的地址。

03绑定对象

把玩家、敌人、目标和数值状态映射到公开语义角色。

04注入driver

评测器在工作副本装入玩家动作控制器。

05注入probe

读取位置、接触、生命值、进度等真实状态。

06隐藏检查

按作者场景参数、路线和预期结果判分。

候选可自选内部节点名与代码结构，只需正确暴露绑定；隐藏输入路线与状态检查条件不是候选填写的。

08 · REAL TASKBeacon Relay

真实 Beacon Relay：拾取电池，踩敌人，存入信标

Pickup：拾取

接触台座电池cell后启动fuse倒计时：三关分别13/12/11秒；电池从绿变黄再变红。

Stomp：踩敌人

带电池从上方踩中敌人，返还2.5秒并刷新空中跳跃；侧碰损失shield护盾。

Deposit：存入

带电池与beacon信标重叠，relay进度增加、点亮一段，fuse停止。

Appendix B.2 真实 GDD：三关共 11 个电池，普通输入路线 6–9 分钟、60Hz。判分必须观察动作对应的对象与进度变化。

Appendix B.2 完整 GDD；Brief 允许自定信标规则，不能把这些机制当作 Brief 的硬要求8 / 14
09 · VERDICT PATH从输入到 PASS / FAIL

已认证输入路线测行为，无输入对照检查成功是否由玩家造成

1从头启动

启动候选，校验公开接口与场景。

2重放输入

按参考路线的动作与时序输入。

3观察状态

读取碰撞、对象出现消失与实时状态。

4检查要求

检查中间目标、最终目标与功能要求。

5无输入对照

同长度无输入也成功，则 route 记 0。

PASS 逻辑

玩家动作触发拾取和存入；探针观察到对象与进度变化，无输入时不发生。

解释性 FAIL

候选按时间自动增加进度并显示胜利，无输入也过关；因此该输入路线记零。

FAIL 由协议推导，非模型 log；无输入对照只排除自动成功，仍要检查途中条件和动作效果9 / 14
10 · SELF-DEMOAgent 可以证明自己的独特实现

demos.json 补足固定 reference route 覆盖不到的功能

独立片段

候选为每段 demo 写出标识、说明和完整输入操作。

统一起点

每段从第一关重新启动，不能注入内部状态或选择隐藏场景。

匹配对照

每段都跑同长度的无输入对照。

不重复计分

多段 demo 证明同一功能，不会重复增加覆盖分。

demo 不必通关整部游戏，但必须实际触发所声称的功能；没有任何片段证明的要求，仍算未覆盖。

14 · VERDICT怎样读这篇论文

它把“想要的游戏”变成动作、状态与视觉三类证据

证据支持

  • 执行检查验证玩法逻辑，多模态模型检查视觉表现
  • 无输入对照排除自动成功
  • 需求遗漏和玩法逻辑错误是主要失败来源
  • 公开语义接口允许候选采用不同内部结构

仍不能确定

  • 六个 Agent 框架、工具与预算分别造成的影响
  • 主榜重复运行与方差
  • 人工标注协议和视觉评分模型身份
  • 逐题检查代码对外部复现者是否可用

截至 2026-10-08，论文未链接正式 benchmark/checker repository。最可信的结论是评测设计方向，而不是把 Table 3 当成纯模型排行榜。
