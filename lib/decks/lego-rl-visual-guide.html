原有执行流程，
用真实修复结果训练模型

LEGO-RL 不改写 Agent 怎样管理上下文和工具。它在模型服务处记录实际生成的 token，在隔离仓库里执行修复，最后用隐藏测试给出 0/1 分。

训练需要对上同一条记录：模型当时读了什么、生成了哪些 token、使用了哪些 MoE 专家。训练程序根据这些记录重算概率，更新模型权重，编码助手的执行流程不变。

一次 rollout 指模型与工具完成一道任务的整段执行记录。Claude Code 仍管理提示、工具调用和历史压缩；训练系统用代理程序（proxy）记录模型请求和返回。

04 · PART 0历史改写、专家路由与异步旧权重是不同问题

历史文字可能被 harness 改写，训练仍须保留模型当时真正生成的 token

HARNESS

历史压缩或工具参数重新排版后，重新编码的文字可能不等于原始生成序列。

PROXY

论文要求保留原始 token、排除对不齐的历史；公开 a3e28f1 的异常分支却会重建，不能一概保证。

MOE 路由

MoE（混合专家模型）每个 token 只用部分子网络。代理保存选择，训练程序用 R3 沿用这些专家。

只更新真实模型生成的位置。Harness 添加的文字和工具返回值不算模型输出；子 Agent 调用单独隔离。

09 · REAL CASE12rambau__sepal_ui-814 · issue #813 / PR #814

第一次设置进度条 total，后续 update_progress 不应再次要求 total

# PR #814 的公开测试调用
alert.reset()
alert.update_progress(0, total=100)
alert.update_progress(50)

# 测试检查

需求和测试来自上游维护者Pierrick Rambaud 提出 issue #813，并在 PR #814 写参考修复与测试；不是训练 Agent 自己写的验收。
训练时隐藏，本文用公开补丁解释Agent 只收到需求和仓库；参考 PR、隐藏测试与评分器不可见。

旧实现：第二次调用报错

50 > total=1

第二次没有传 total，旧代码又读取默认值 1；检查“进度必须在 0 到 total 内”后抛 ValueError，目标测试失败。

参考修复：沿用已初始化的总量

n=50 / total=100

进度条已存在时读取 self.progress_bar.total，更新后进度为 50、进度条可见。完整判分还要求原有通过测试不回归。

19 · LIMITATIONS论文能证明什么，不能证明什么

有端到端提升，也有生成对齐、案例复现和对照实验的缺口

重复次数训练方差未知三种 harness 各训练一次，主表使用验证最高分；不是最终固定 checkpoint 成绩。
任务选择筛选只用一种 harnessQwen3.6-27B + OpenHands SDK 估计难度，未证明对三种程序都最优。
论文与代码不同历史重建不一定被排除a3e28f1 可能重编码 assistant 段并保留占位概率；官方脚本关闭概率重算，模块单独启动却默认开启。
案例与输入范围完整测试包未公开sepal_ui-814 的 Harbor 包未完整发布；这版代理对真实多模态请求也不收集训练 token。
同步／异步对照硬件吞吐不完全匹配2.5× 是实测；1.9× 是校正估计，并未按相同吞吐重新实验。
行为变化相关变化不能确定因果重读、测试与推理文字同时变化，没有只改变其中一种行为的对照。

20 · TAKEAWAYS对 Claude Code / Codex harness 训练有用的检查项

训练原生 coding Agent，要把实际生成记录与验收结果对应起来

实际生成

保存原始 token

正常路径保留模型实际输出；公开版本的历史重建回退不能保证同样准确。

REWARD

执行结束再注入验收文件

Agent 执行时看不到隐藏测试、参考修复和评分脚本。

任务难度

保留有组内差异的任务

同题全错或全对都不给相对学习信号；固定题池会随模型变化而变易。

诊断

从均值追到具体记录

查结束原因、工具调用、任务变化，以及生成和训练概率是否一致。

尚未验证

一个模型通用多种 harness

论文分别训练三次；不能据此宣称已学到跨 harness 的通用行为。

INTEREST
