02 · 模型与流程的角色先把名词对应到对象

三种角色，只有当前模型的参数在更新

同一份 Qwen3-8B 初始权重被放进不同的输入条件和更新角色。

当前 student pθ

只看原题写一份完整回答，训练只更新它。

控制程序 Hθ

调用当前模型、检索样例或生成解题计划（plan），最后组装 teacher 的输入文本。

冻结 teacher pθ̃

初始 Qwen3-8B 的冻结副本；多看 harness 输入，判断下一个 token 的概率。

On-policy rollout

当前 student 此刻自己写出的回答。参数更新后，下一批回答也会改变；不经外部流程的回答简称 direct rollout。

Terminal context C

terminal 指流程末端，不是命令行；它是 harness 最终交给 teacher 的完整输入。

Confirmer / challenger

程序先生成初步标签（draft）。与它至少共享一个标签／没有共同标签的历史样例分为这两组，是数据行，不是 agent。

16 · 结论与缺口兴趣程度 9 / 10

方法骨架值得读，当前公开代码不能直接当作论文协议

当前模型自己生成回答，冻结副本多看辅助输入；训练比较同一回答上每个位置的下一词概率。

证据支持

  • 两套 harness 下，不挂 harness 的 OPHSD 领先 OPSD / GRPO
  • 132/156 道原本仅 harness 能解的题被 student 解出
  • 真实 case 展示规划习惯，以及错误检索怎样干扰结果
  • 仓库给出训练代码、harness、3×10K 数据与固定终点 CSV

证据尚不支持

  • 真实工具执行可以被模型参数替代
  • 任意 harness 训练后都应拆掉
  • 增益可完全归因于 plan / verify 流程
  • 当前公开代码路径与论文协议等价

复现优先项：修复 solution 传递；确认 KL 方向；固定“最佳 checkpoint / 固定训练终点”口径；补答案提示、错误 context 和真实工具反馈的消融。
