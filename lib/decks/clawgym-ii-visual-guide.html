02 · MOTIVATION保留部署时真正使用的 harness

训练框架常自行管理工具循环；真实部署程序还会重试、压缩历史和调用子任务

Claude Code、OpenClaw 会自己构造提示、执行工具、重试、调用子 Agent 和压缩上下文。把这些过程重写进训练框架，模型看到的输入与操作过程就不再与部署时相同。

WHITE-BOX

训练器自行管理执行顺序

可以直接定义状态、动作、工具循环和得分分配，但原部署程序的行为被替换了。

BLACK-BOX

只观察模型 API

Harness 内部逻辑保持不动；可见的是每次模型调用和最终工作区。

TARGET

把任务分写回有效生成片段

必须恢复长轨迹、过滤辅助分支，并保留 rollout 时的 token 与概率。

06 · TRAJECTORY FILTERING先判断哪条分支代表主任务

同一棵树的每个末端分支，不都该收到主任务分数

DROP

被重试替代的旧分支

按历史压缩点分段，每段保留最长有效延续；被重试替代的短分支丢弃。

DROP ROLLOUT

过度分叉

末端分支数超过阈值，整次任务记录视为异常；阈值未披露。

EXCLUDE

生成摘要 / 执行子任务

这两类辅助调用不训练；压缩后继续完成主任务的交互段仍保留。

KEEP

主 Agent 的有效路径

保留有效的根到末端路径，同次任务的共享前缀只计一次。

来源：论文 §3.2.2–§3.2.3。分支数量上限未公开。
07 · GRPO任务分属于整次尝试，不是单独某条分支

同题多个尝试先算相对得分，再写回保留树节点

分组单位

优势单位

仍未解决

08 · PPO各分支独立估计生成步骤的回报

PPO 对兄弟分支分别回传任务分，γ = λ = 1

ESTIMATOR
Âₜ = Rᵢ − Vφ(sₜ)

每条路径在末 token 收到任务分，再用 GAE 估计此前各步的回报。GAE 是广义优势估计；回传不跨分叉点进入兄弟分支。

TRADE-OFF

价值模型要从早期状态预测最终回报，且不按时间衰减。论文尚未精细区分各分支对最终结果的贡献。

09 · TOKEN FIDELITYharness 可改文字表示，不能改训练 token

保留实际生成 token，截断概率比减少生成与训练不一致的影响

1 · SAMPLE生成端保存原始输出 token 与生成时的对数概率。
2 · ACT原程序读文本可以格式化工具调用、重新序列化消息。
3 · TRAIN训练器读原始 token不从改写后的历史反推输出 token。
4 · CORRECT每个 token 的概率比用截断重要性权重减少概率不一致的影响。
wₜ = min(exp(log πold(aₜ|sₜ) − log πrollout(aₜ|sₜ)), c̄)这是偏差与方差的折中。论文没有公开 c̄ 的数值。
来源：论文 §3.2.4，Equations 9–10。

20 · TAKEAWAYS对 Claude Code / Codex harness 研究最值得带走的点

它提供了训练桥接算法，尚未证明模型能通用多种执行接口

接入方式模型 API 可作为训练接入处原程序执行工具，代理记录模型实际生成，结束后获取任务分。
核心算法分叉执行记录需要树结构共享前缀去重；按压缩点分段，排除重试短分支和辅助生成。
任务评分任务分数是连续完成度公开 runner 对 final_score 求平均；论文称 Pass@1，二者表述并不完全一致。
实验范围训练方差未知没有重复训练或置信区间；混合训练也缺完整数值表。
复现缺口核心训练代码尚未公开2026-10-14 检查论文代码仓库为空，调用树和训练实现无法核验。
下一步对照跨 harness 因果实验固定任务、原始权重、执行次数与生成额度，再做训练程序×测试程序的配对实验。
