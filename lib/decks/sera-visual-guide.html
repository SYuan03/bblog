01 · 核心问题arXiv:2610.04902v1 · 2026-10-04

学会评价子任务，能否也把任务做得更好？

SERA 用强化学习训练同一个 Qwen3-4B 模型执行、委派和评价。模型写出子任务的评分标准（rubric）；用它奖励执行，再训练标准怎样写，TextWorld 才明显改善。

03 · 为什么需要评价训练Sections 1, 3.1

根目标可检查，临时子目标需要结合上下文评价

执行 E

子 Agent 是否完成目标？根任务仍用程序成败；训练的非根节点用 rubric 连续分。

委派 D

这次委派承担多少工作？用成功树中的叶节点占比作近似。

评价 RT

rubric 能否把成功分支排在失败前？外部真实标签监督生成标准的动作。

对照方法 RAO（Recursive Agent Optimization）给每个节点外部二元成败奖励。SERA 三个角色共享参数，但子 Agent 的执行输入与评分调用分开。

04 · 执行奖励Section 3.2；Runtime/rubric/prompts.py

子 Agent 做任务；独立评分调用读取标准和结果

执行路径

父 Agent 发起委派 → 子 Agent 接收子目标、上下文和工具 → 执行并返回轨迹/状态。

子 Agent 不接收 rubric。它可以继续递归委派。

评价路径

委派前的信息 → 写 4 至 8 项 rubric → 固定这份标准 → 读取子 Agent 结果评分。

E：根用程序成败，非根用连续分；更新求解和委派输出，不更新评分输出。

生成器只能看到委派前信息。异步路径并发生成 rubric 与执行子 Agent；RT 可先采集分支，但仍不给生成器看子结果。

06 · 评分标准怎样训练Equation 3；rubric_generation_ranking/stage.py

只训练“写 rubric”这次动作，评分输出不进入优化器

Lrank = meani∈success,j∈failure max(0, 0.2 − si + sj)rubric reward = −Lrank；全成功/全失败组跳过

RT 更新

只更新生成 rubric 的输出 token。

RT 不更新

评分调用与执行轨迹不直接进入这个阶段的优化样本。

仍有风险

角色共享参数；其他阶段也会改变评分行为，不能据此排除奖励漏洞。

07 · 委派奖励Section 3.3；leaf_credit.py

一次委派覆盖多少叶节点，就分到多少结构奖励

rleaf(e) = root_success × |leaves under e| / |all leaves|
根任务成功某次委派覆盖 2 / 3 叶节点

发起这次委派的动作得到 2/3；只训练对应语句的 token。

根任务失败所有委派奖励都是 0

完整 SERA 不再按子任务成败过滤。叶节点默认等权，拆得更碎不等于贡献更大。
