让 Claude Code 看完整历史，再改模型外的执行程序

保存历次候选的代码、分数和原始执行记录；提案模型自己查错和改代码，基础模型权重始终不更新。

1 · Claude Code 读历史，写出新候选用文件搜索和脚本查旧代码及原始记录，不必先把所有失败压成一份摘要。
2 · 独立程序检查接口、执行任务、计分候选提出者不能自己决定评测结果；每个候选的源码、分数和记录再进入下一轮历史。

03 · 搜索循环提案 → 检查代码 → 评测 → 保存记录

提案模型写候选代码；外层程序控制验证、计分和版本选择

1 · 保存历史文件系统保留每个候选的代码、搜索分数和原始执行记录。
2 · 提案模型选读并改写Claude Code 自己检索相关文件，写出一个新 harness；基础模型权重不变。
3 · 外层程序独立评测检查候选接口，运行任务，产生分数与新的执行记录。
4 · 记录并继续搜索新候选回到文件系统；前沿保留准确率与成本互不全面胜出的程序。

05 · 邻近路线改什么 · 看什么反馈 · 谁负责更新

提案模型能检索历次代码与原始记录，不必只读摘要

路线改什么提案模型看什么与 Meta-Harness 的边界
GEPA提示或其他文本产物一个候选的执行反馈或摘要反馈较丰富，但不保留所有候选的原始记录。
AlphaEvolve / OpenEvolve指定函数或程序历史程序与汇总分数搜索代码；可读到的原始排错记录较少。
TTT-Discover推理时产生的程序等产物近期窗口；PUCT 优先复用高分且少访问的候选搜索规则不同；提案输入受预设结构限制。
ACE / MCE记忆与自然语言技能描述在线样例与反思用作待优化执行程序的基线，不是通用代码优化器。
HarnessForge / Co-Harness执行程序与模型权重失败归因与成功轨迹共同优化模型与程序的配合；本文只改程序。
GEPA · 改提示与文本

提案者读取单个候选的执行反馈或摘要；原始记录不会作为全部候选的历史供它自由检索。

AlphaEvolve / OpenEvolve · 搜索代码

可看历史程序与汇总分数；原始排错记录较少。

TTT-Discover · 推理时搜索

读取近期窗口，用 PUCT 复用高分且少访问的候选；输入受预设结构限制。

ACE / MCE · 改记忆与技能文本

利用在线样例与反思；本文将其作为分类任务中的执行程序基线。

HarnessForge / Co-Harness · 程序与模型共同优化

利用失败归因与成功轨迹；Meta-Harness 只改模型外程序，基础模型权重保持冻结。

来源：论文 §2、Appendix F；HarnessForge arXiv:2606.01779；Co-Harness arXiv:2607.22688。

19 · 结论与限制保留结果，也保留适用范围

可检索的完整历史能改善程序搜索；跨任务基准的泛化仍需验证

已经验证

原始记录有用

提案模型读原始记录、写代码；外层程序检查导入、跑评测、记录候选，并在选定后做最终测试。

搜索产物可检查，也能换基础模型测试。

尚未验证

泛化与归因仍不完整

只研究 Claude Code + Opus 4.6 提案模型；TerminalBench 没有独立题目；开源仓库是整理后的版本，仅确认能运行。

还需比较不同提案模型、独立测试任务、搜索成本与代码复杂度。
