路线主要改什么何时发生核心证据

07 · 一轮执行默认最多 25 轮；Executor 1800 秒，Manager/Auditor 各 300 秒

Executor 的“我做完了”只能触发审计，不能直接改 task state

1 · 读取

读取进度

Manager 看到原任务、当前进度和历史核验报告。论文设计不让它访问环境。

2 · 分派

选一件事

写目标、验收条件、不能改的对象和相关证据引用。

3 · 执行

新会话

Claude Code 或 Codex 只收到本轮信息，并可修改环境。

4 · 报告

自述结果

输出做了什么、产物在哪里、遇到什么问题。此时仍未验证。

5 · 核验

只读重查

从环境核验文件、应用状态、日志、截图与已保存结果。

6 · 更新

更新进度

Manager 采用核验支持的事实，保留缺项和尚未可信的结论。

7 · 决定

下一轮

继续执行、询问用户、报告受阻，或结束。

08 · 内部核验过程审计，不是 benchmark 最终评分器

Next: done 必须跨过三个独立条件

当前源码解析前三行

Status: complete | incomplete | blockedIntegrity: clean | suspect | violationContract audit: aligned | unknown | needs_revision | invalid

分别判断是否完成、核验是否违规、验收要求是否忠于原任务。正文再列证据、缺项、阻断条件和进度更新建议。

源码明确拒绝哪些结束请求

  • Claude Code 适配器比较工作区前后快照；发现写入就标为违规。
  • 仍有阻断项时，complete 会被改成 incomplete。
  • Manager 请求结束，最近报告必须同时是 complete、clean、aligned。
complete：已完成
clean：未发现核验违规
aligned：验收要求与原任务一致
缺一项 → 拒绝结束，送回缺项

09 · 代码适配保留原执行程序的内部循环，外层每次启动新会话

上下文不继承旧聊天，任务文件仍保留

Claude Code--print --output-format stream-json，关闭自动记忆和提示历史；按角色禁用部分工具。
Codex CLIcodex exec --json，从标准输入读取本轮提示；可配置模型、思考档位与 MCP 工具连接。
新会话每轮生成唯一提示文件，在同一任务工作区启动新进程，设置独立超时。

设计边界不等于硬沙箱

保留原任务、当前进度、验收要求和明确引用的核验报告；不传完整执行轨迹。
固定源码允许 GUI/CLI Executor 使用重叠工具；Auditor 仍可调用 Bash 和计算机操作工具。
Codex 默认绕过自身沙箱；Claude Code 的角色禁用名单和快照检测也不是进程隔离。
源码 cli_agent.py:47–119；adapters/claude_code.py:45–184；adapters/codex.py:47–104。

12 · 真实案例 / DOC_TASK_2 + DOC_TASK_4LibreOffice Writer / Calc

视觉完成、文件语义、修复前证据是三种不同的验收条件

DOC_task_2：统一标题样式

Baseline 发现 FakeBoldParagraph 后直接编辑 XML，没有按要求在 LibreOffice 中操作，也未证实 PDF 导出，judge 给 0.00。

LongHorizon 通过 GUI 应用 Heading 1，逐页复查；Auditor 随后解析 XML，确认 15 个标题为 Heading_20_1、outline-level=1，得 0.89。

先 GUI 修改，再 XML 核验

DOC_task_4：修复 VLOOKUP

Baseline 已保存部分初始错误截图，但证据未收全就改 XML；重开仍有 Err:510，文件与截图序列不一致，得 0.45。

LongHorizon 把缺失的修复前截图留作待办，收全后才修改，再核验九张前后截图，得 0.87。

先收全修复前证据，再修改

13 · TERMINAL-BENCH 案例最终测试与内部核验仍是两层

文件存在、可以编译，不等于所有测试通过

SQLite：编译并启用覆盖率

gcov 用于检查代码哪些部分运行过。对照的编译和 PATH 测试通过，但覆盖率测试失败，reward 0。

LongHorizon 在六轮中检查源码、编译位置、覆盖率符号、.gcno 文件和最终保存位置，三项测试全过，reward 1。

mystery binary：独立复刻图像

对照文件存在且能编译，但图像相似度测试失败。LongHorizon 交付独立 C 程序，静态编译，gzip 后小于 2000 字节，不调用原程序。

公开案例中图像一致，移走原程序后 MD5 仍一致；九轮后 reward 1。未展示多类输入，不据此宣称普遍等价。

16 · 结论与边界整套系统有增益，各组件贡献仍未拆清

可复用的是任务状态与明确验收条件

已有证据同模型、同执行程序有总体增益WeaveBench 和 Terminal-Bench 的配对结果支持整套系统有效，尚未控制相同总 token 成本。
缺少消融三个组件没有拆开检验无法判断收益分别来自进度记录、新会话、Auditor，还是更多计算与 GUI/CLI 分派。
最强反例原本满分也会被做坏OSWorld Opus 子集的 021、030 都从 1 降到 0；Weave Desktop 平均分 0.8671→0.8465。
下一步实验检验核验准确性与成本测误放行、跨模型互审、固定总预算和各组件贡献；OSWorld 的工具变化也要单独控制。
