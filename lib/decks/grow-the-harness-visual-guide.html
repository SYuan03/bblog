把搜索、重试和结束等重复判断写进代码，供下一道任务复用

5 / 6六组任务集 × 模型设置中，五组平均成功率最高

9.6/10博客作者个人兴趣程度

这里的 harness 是调用模型和工具、保存中间结果、决定何时停止的程序。优化器根据失败任务的执行记录 trace 修改实际运行过的函数；若保留验证题上的成功率下降，就恢复上次通过检查的代码与训练进度。模型权重不变。

02 · 两种可用资源单次输入是临时的；代码可留给后续任务

Context 是本次调用能读到的内容；harness code 是下一道任务还能执行的程序

每次放进 context

模型读问题、工具输出和此前的操作记录，重新决定是否搜索、换关键词、重试或提交答案。Context 指这次模型调用收到的上下文。

这类做法把很多控制判断交给模型；相似问题也要再调用模型做一遍。

跨任务写进 harness

把可直接检查的规则写成函数，例如过滤重复结果、解析工具返回值、处理错误和检查停止条件。需要理解当前证据时再调用模型。

论文称这种跨任务积累可执行函数的做法为 persistent program growth。

模型和工具接口固定，作者只修改控制程序。初始程序有入口和接口，但没有预先写好的完整解题策略。
来源：Introduction、Section 3.1、Related Work

07 · 训练循环正文 §3.5-3.6 与 Table 5 的协议

先积累候选修复；累计修好 Q 道题后，才检查是否损害原有能力

1 · 填满窗口

当前程序跑尚未处理的训练题；只把失败题及执行记录 放入容量 K 的窗口。

→
2 · 修改函数

优化器同时看这些失败；只改执行过的函数和入口，改动或新增不超过 L 个函数。

→
3 · 重跑窗口

候选成为临时版本。移出已修题，更新未修题的执行记录与尝试数；继续累计修复数。

→
4 · 累计到 Q 再 gate

在保留验证题上重测。成功率不下降就保存完整状态；下降则恢复上次通过的状态。

BrowseComp-Plus

K=8，Q=1，Rmax=5，L=10；训练题超时 900 s。

WebArena-Verified

K=4，Q=8，Rmax=5，L=10；训练题超时 1,800 s。

Q 的含义

自上次 gate 起累计修好的题数，不是一次窗口必须修好的数量。最终测试 50 题不参与训练。

原文冲突：Algorithm 1 把 Q 写成单窗口门槛，并立即 gate；按它执行，K=4 的窗口不可能修好 Q=8 题。正文与 Table 5 则把 Q 定义为累计 gate 间隔。没有公开代码可裁决，不能据此声称已精确复现。

08 · 函数级修改只改失败记录中运行过的函数

最终 0/1 分只说明成败；执行记录还指出这次实际运行了哪些函数

trace τᵢ = (
  task xᵢ,        # 题目
  execution DAG Gᵢ,
  output yᵢ,     # 最终输出
  verdict oᵢ,    # 测试程序给出的 0/1
  usage uᵢ       # token、费用、耗时
)

editable Aₜ = {main}
  ∪ 窗口中失败任务实际调用过的函数

Execution DAG

把函数、模型和工具调用记为节点；边表示谁调用了谁。每个节点记录输入、输出或错误、父节点和耗时。

允许修改

入口 main、失败记录中实际运行过的函数，以及少量新增辅助函数。

禁止修改

没有执行过的已有函数；不能删除函数、改接口，或写入题目 ID 和预期答案。

限制搜索范围

即使程序越来越大，每轮也只让优化器修改与这批失败有关的部分。

把多个失败放在同一个窗口，让优化器寻找可复用的修复

→
失败窗口

窗口最多 K 道失败题。每题保留最新执行记录 trace 和已尝试修复的次数。

→

已修题离开；未修题带着新 trace 留下，尝试数达到 Rmax 后退出。再用新失败题补满窗口。

10 · 回归验收费用更低不能抵消成功率下降

Gate 只看保留验证题的成功率；下降就撤销这一段修复和训练进度

接受这一段更新

自上次 gate 起累计修好 Q 题后，若 SRG(current) ≥ SRG(hgate)，就保存当前代码、题目读取位置、窗口、计数和训练记录。hgate 是上次通过检查的版本。

恢复上次通过的状态

若成功率下降，撤销从 hgate 之后积累的整段修复。题目读取位置、窗口、计数和记录也恢复；不只是撤销最后一处代码改动。

训练结束时，尚未检查的改动还要做一次最终 gate。论文把这称为 success-first：运行费用更低，不能补偿验证成功率下降。

来源：Section 3.6；采用正文累计 gate 协议，非 Algorithm 1 单候选门槛

18 · 结论与限制对 coding harness 的启发

可借鉴如何积累修复和回滚；论文尚未公开学到的 harness

可以借鉴

  • 把可直接检查的重复规则写成代码，理解当前证据时再调用模型。
  • 用失败任务的执行记录，限制这轮可以修改哪些函数。
  • 累计修好 Q 题再 gate；保留最近通过的完整状态，失败时整段恢复。
  • 同一任务集的 harness 换用 4B 至 120B 模型后仍可使用。

仍缺少的证据

  • 未公开代码、学到的程序、任务划分和逐任务记录。
  • Algorithm 1 的单窗口 Q 门槛与正文累计间隔冲突。
  • 未报告离线优化器和评测器成本，无法算训练多久回本。
  • 只训练两类专用 harness；消融每组一次，最终 50 题的置信区间较宽。
