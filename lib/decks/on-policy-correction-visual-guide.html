为弱模型调好执行程序后，模仿强模型的完整记录反而可能变差

Harness 是调用工具、管理上下文和检查提交的外层程序。为 Qwen 调好的版本记为 h*；Qwen 在它上面达到 78.0%，完整模仿 Gemini 后降到 63.1%。

作者改用 on-policy correction：从 Qwen 自己的失败记录出发，只替换定位到的一个错误回复及工具调用，其余记录保留。微调后仍用原 h*，平均成功率达到 79.7%。

04 · CONCEPT模型更新后，原程序预期的检查和提交顺序可能改变

作者把模型执行习惯与外层规则的配合，称为 model-harness fit（模型与执行程序的适配）

原始学生执行方式

h* 围绕这种行为调过

  • 把问题拆成具体子任务
  • 在要求的位置调用工具和检查
  • 完成一次验证后明确提交
  • 按学生常见错误调整恢复规则
⇄
完整模仿后的变化

学到规则，也可能改坏执行习惯

  • 说明更短，可能更早作答
  • 跳过原程序依赖的中间检查
  • 或反复验证，始终不提交
  • 计算规则使用增加，成功率仍下降
来源：论文 §3.3.3、Appendix D。以上是作者的机制解释，非独立因果证明。

10 · SFT-CORRECTION学生访问到的状态 + 一个专家重写

只替换学生记录中的错误回复；后续学生内容没有重新生成

01 · 执行学生失败记录Qwen 在 h* 下执行任务，保存模型回复和工具反馈。
02 · 定位定位到的出错 turn定位与失败有关的一次回复；turn 是一次模型回复及工具调用。论文未说明如何保证它是最早出错的位置。
03 · 重写专家生成 3 个候选输入题目、此前记录和失败检查点；输出一句修正策略与工具调用。
04 · 选择质量评分者选 1 个只替换这个 turn，前后学生步骤保持原样。
05 · 微调约 500 条约 400 条修正与约 50 条学生成功记录，最终 79.7%。
质量评分不是环境重跑验收。更改工具调用可能改变后续环境状态；论文未披露修正记录的重新执行比例，不能把约 400 条称为“验证通过的成功轨迹”。
来源：论文 §3.4、Appendix B；约 400 + 约 50 未完全相加到约 500，差额未解释。

# Appendix B 的说明性重建；函数名非官方 API。
def make_example(student_rollout, failed_checkpoint):
    turn = localizer.locate_failing_turn(
        rollout=student_rollout, checkpoint=failed_checkpoint,
    )
    candidates = [
        expert.rewrite_only_this_turn(
            task=student_rollout.task,
            prefix=student_rollout.before(turn),
            failed_checkpoint=failed_checkpoint,
        )
        for _ in range(3)
    ]
    patch = quality_judge.select_best(candidates)
    # 只替换 turn；其余内容保留。此处没有环境重跑。
    return student_rollout.replace(turn, patch)

18 · TAKEAWAYSfor Claude Code / Codex harness research

权重更新会改变执行习惯；训练后要重新检查与原 harness 的配合

已有证据

完整专家轨迹未必是安全训练单位

在学生自己访问到的失败状态上局部修正，可以保留更多原有执行步骤。本实验仍部署同一个 h*，平均从 78.0% 到 79.7%；不是移除工具或 harness。

下一步如何验证

在完整 coding harness 中做同条件比较

同一批隔离仓库任务上，比完整模仿、单次回复修正和短区间修正；人工检查错误定位，再把修正放回环境重跑。更新模型后，复测工具调用、验证和提交是否仍符合原规则。
