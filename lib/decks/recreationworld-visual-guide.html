08 · 测试构造生成并验证测试后才冻结评测

隐藏测试以原软件运行结果为准，先回放再人工复核

1 · 发现功能

从源码或页面分析找功能入口与可测试状态。

2 · 实际操作

实际操作原软件，记录指定动作产生的结果。

3 · 生成测试

准备固定输入文件、动作序列与程序/视觉观察条件。

4 · 重置回放

在重置后的原软件上跑；不稳定或不通过的测试淘汰。

5 · 复核冻结

人工检查输入、动作与预期观察，随后冻结。

论文没有报告复核人数、标注者一致性或驳回率。能确认有人审核，不能据此声称审核高度一致。

10 · 两种检查通道精确状态与实际画面

程序与画面互补，但必须区分缺少画面与 judge 失效

Prog

用 AT-SPI / AXUIElement / UI Automation / UiAutomator / DOM-ARIA 等平台接口读取控件文字、状态、导航与计算结果。构建或启动失败使整个任务为 0。

VLM

在固定检查位置截取完整应用窗口，用 Qwen3.7-Plus、temperature 0 判断布局、颜色、绘图区和图例等观察条件。输出必须逐项给 JSON 判断。

SYSTEM_PROMPT: pass=true only when the assertion is clearly and fully satisfied

missing / incorrect / placeholder / visibly mismatched element → FAIL

论文 §4.4 要求传输或解析错误重测。Web 当前代码另有处理：缺截图记 0；judge 无判断记 None，排除视口并重算权重；全站无判断时退回图像相似度。不能据此确认历史榜单已全部重测。

来源：Section 4.4；官方 src/recreation_bench/common_vlm.py

15 · 结论与边界实验支持什么，还有哪些缺口

最完整的是可执行链路；最需要补的是 VLM 校准、重复运行和训练消融

论文已经讲清

  • 一套五平台交付规则连接界面探索与写代码。
  • 隐藏测试先在原软件重置回放，再经人工复核冻结。
  • Prog 与 VLM 互补，五平台等权聚合。
  • 强模型平均分较高，但程序检查全部通过仍罕见。

仍然不能推出

  • 有限隐藏测试不能证明行为完全等价。
  • 视觉判分没有人工校准或一致性报告。
  • 无法排除模型预训练时已经见过这些公开软件。
  • 单次执行不能说明小分差稳定，也不能把整套配置的节省归到单一组件。
让原软件提供可探索的行为，再用固定输入与隐藏回放检查成品。执行记录还能展示 Agent 怎样交替使用界面和代码工具。
来源：Sections 5-8、Appendices B-D、官方仓库
