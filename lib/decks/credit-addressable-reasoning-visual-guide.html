Code-CoT 让模型用代码、推理和操作标签写几何解题过程，每个完整步骤叫 event。CE-GRPO 固定某个 event 前已有的内容 prefix，从这里生成四种完整后续 future。最终成绩的差异用于训练新生成的步骤和全部后续；prefix 不更新。

02 · 训练反馈一个最终分，对应多个决定

GRPO 用最终得分比较整条回答，同一回答的生成 token 共用一个相对成绩

题目

给出原图和问题，模型要识别对象、选定理、构造和计算。

→
同题多条回答

每条都生成完整推理与答案，检查程序给最终分 R。

→
相对得分 advantage

算这条比同组平均好多少；回答里每个生成 token 共用这个值。

Aᵢ = (Rᵢ − mean(R)) / (std(R) + 10⁻⁶)
Credit assignment 指最终得分应该鼓励哪些生成步骤。若早期把几何关系判断错了，后面沿错误前提推导，整条得分无法单独比较早期决定的替代方案。
来源：Introduction、Equation 3；GRPO 是组相对强化学习更新方法
03 · 研究问题先找到完整步骤，再比较它的替代后续

训练要从某一步分叉，程序首先得找到这一步的完整边界

表示缺口：representation gap

自由文本把对象关系、角度判断和辅助线构造埋在句子里；任意 token 边界未必对应一个完整几何步骤。

训练反馈缺口：credit gap

整条回答的最终分数，不能直接说明“固定此前内容，换掉这个决定后会怎样”。需要从同一个位置生成多种后续来比较。

credit-addressable reasoning = inference event boundary = training branch boundary

作者的意思是：推理时完整步骤的起点，也用作训练时重新生成的起点。这个步骤的全部后续仍一起训练。

来源：Section 1；术语为作者提出
04 · 图像与代码对照代码补充图像，不替代图像

代码不能代替图像；图像与外部生成代码一起输入时，六个模型都更好

只给图像 I

模型直接读图。六个模型的平均准确率范围从 45.5 到 92.3。

图像与外部代码 I+C

六个模型全部提升，绝对增益为 0.7 到 18.4 个百分点。

只给自产代码

三个开源模型比 只给外部代码 低 11.7 到 16.6 个百分点，说明可靠生成代码本身就是瓶颈。

所以 Code-CoT 保留原图，让同一个模型自己生成代码，并用 SFT 明确教会这种协议。只写一个 prompt 的平均分反而从 67.95 降到 49.26。

05 · 回答格式固定标签协议，中间 think/action 可重复

Code-CoT 用标签让程序找到识图代码、计划、操作与答案

<perception>带行号的可执行 Matplotlib 图形代码
PLAN:一行解题计划
<think>一个完整推理步骤
<action>引用代码／辅助构造／建坐标系
<think>可继续交替生成推理与操作
<answer>恰好一个非空答案块
完整 think 或 action 块叫 event。候选池只包含这些完整块；识图代码、计划、答案和无标签文字都不会作为重新生成的起点。图中六块是格式示意，不表示每条回答恰好六段。

06 · 步骤类型每类完整步骤改变什么

步骤类型决定怎样改变当前几何状态，以及程序检查什么

步骤类型作用有效条件
think根据当前图、代码和前序步骤推导起止标签完整；不计入操作有效率的分子或分母
reference第一次使用视觉事实前，取回识图代码行行号存在、内容逐行匹配、最多 8 行
auxiliary添加连线、延长线、中点、圆或变量对象已存在；新对象有具体可执行代码；操作类型受支持
coordinate建立坐标系并给对象赋坐标调用 set_frame；没有省略号；坐标是具体值

结构有效的回答至少有两个操作。引用代码一致不保证原图事实正确，视觉保真度另由 Table 4 的模型评分检查。

来源：Appendix A.1、Table 8

08 · 训练评分由规则程序评分，不另训 reward model

格式坏了直接 −1；格式有效时，看答案、操作有效率和行为惩罚

R = -1, if structurally invalid
R = clip(correct + 0.3 × valid_actions / all_actions − penalties, -1, 1.3)

答案分 correct

答对给 1，答错给 0；选择题需选项完全匹配，数值题容许 1% 相对误差。

操作有效率

引用代码、辅助构造和坐标操作各自按规则检查。通过的操作数除以总操作数。

行为惩罚

重复操作、重复文字和答案泄漏分别扣分；论文未公开阈值、权重和检测逻辑。

最高 1.3：答案正确、所有操作有效、没有惩罚；错答但操作全有效且无惩罚为 0.3。

来源：Equation 2、Appendix A.3；完整 checker 实现尚未公开
09 · 分支起点标签先定允许的位置，不确定性再排优先级

Selector 先提两个分支候选；是否关键，要看重采后最终分有没有差异

第一个候选：think

默认第一个完整推理块。只有另一个 think 的 type-normalized entropy 高出 1 个标准差以上，才替换。

第二个候选：action

选择归一化 entropy 最高的操作块。另以 15% 概率，把一个候选替换成随机完整 event。

Entropy 用 top-20 候选概率近似生成不确定性，再在同类完整步骤内标准化；未公开剩余概率和零标准差的处理。

训练只用返回的第一个候选；离线验证才同时测两个。从同一个 prefix 生成的完整后续（sibling futures）若得分不同，这里才被计为 critical event。选择器本身不先给“关键”标签。
来源：Equation 4、Appendix A.4；selector 为选择器，event 为完整带标签步骤

13 · 相关工作表示与训练须对应同一个完整步骤

现有工作通常只解决“结构化表示”或“给中间步骤分配得分”中的一边

18 · 结论与限制已有机制与复现、评测缺口

几何步骤能作为分支起点；当前证据尚不足以比较训练效率和通用性

论文内已测

  • CE-GRPO 九项平均 76.04，比整条执行记录 GRPO 高 3.43 个百分点。
  • GeoLaux-mini、MM-Math 增益较大，VisOnlyQA-Syn 和 Geometry3K 则较低。
  • 识图代码对可见事实的宏平均覆盖分从 55.21 到 80.43；渲染成功率到 99%。
  • 推理只生成一次完整回答，不做测试时分支。

不能据此确认

  • 官方仓库只有 README，没有代码、数据、checker 或 checkpoint。
  • CE 使用 64 张 A100、每题 4 次尝试；整条执行记录 GRPO 用 8 张 MI300X、8 次尝试，不是等算力。
  • 3,270 个 prefix 固定来自初始 SFT 模型，未比较训练中刷新。
  • 强模型合成和评分没有人工校准；主结果缺重复训练，迁移到一般代码任务未测。
博客作者兴趣度 8.7 / 10。优先补公开实现、等 token 预算对照和多随机种子实验，再判断这种分支训练的收益。
